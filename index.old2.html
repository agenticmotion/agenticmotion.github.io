01 / The production gap

A successful run proves almost nothing.

Building an agent that works is one problem. Building an agent that can be trusted to operate inside a real system is another.

The demo works.
Now define what happens when it doesn't.

Production introduces permissions, state changes, tool failures, budget limits, retries, side effects, stale memory, human intervention, and failures that arrive when nobody is watching.

01

What is this agent actually allowed to do?

02

Which actions require approval—and where is that boundary enforced?

03

What happens when a tool fails, times out, or returns unexpected state?

04

Can the system stop an agent loop before cost or side effects run away?

05

Can an operator reconstruct why a consequential action happened?

06

Can a failed operation be safely retried without duplicating its side effects?

07

What happens at 2 a.m. when nobody is watching?

07 / Engineering questions

Answers for the architecture review.

What is an AI agent architecture?

It is the system design around an agent: runtime behavior, state, tools, permissions, memory, orchestration, evaluation, observability, budgets, and recovery—not just the model or prompt.

How do you build a production-ready AI agent?

Define the workflow and authority boundary, instrument execution, evaluate expected and degraded behavior, constrain costs and side effects, and design explicit intervention and recovery paths.

When should a company use multi-agent systems?

When the workflow has a concrete architectural reason for multiple independently bounded roles or execution contexts. More agents should not be treated as an automatic improvement over a simpler design.

How do AI agents use tools and APIs safely?

Through explicit permission boundaries, scoped credentials or capabilities, approval gates for consequential actions, execution budgets, audit trails, and recovery behavior for failed or partial operations.

How do you evaluate AI-agent reliability?

Evaluate the behavior that matters to the workflow using representative test cases, regression suites, traces, graders, error analysis, and deployment gates tied to defined acceptance criteria.

How do you add human approval to autonomous workflows?

Define explicit intervention boundaries, persist enough state to resume safely, expose the relevant trace and context to the operator, and make the post-decision path deterministic where possible.

How do you prevent unsafe agent actions?

Treat authorization as an architectural boundary rather than relying on instructions alone. Scope tool access, constrain side effects, require approval where appropriate, enforce budgets, and record the resulting trace.

What is an AI agent control plane?

It is the operational layer that governs agent authority and execution: permissions, budgets, intervention, state visibility, auditability, and controls for stopping, escalating, or recovering a run.
